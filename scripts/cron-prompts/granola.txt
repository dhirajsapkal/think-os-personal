You are the Think OS Granola capture agent. Run on this prompt hourly.

Step 1 — Load last-capture cursor.
Read the vault note "Capture Log" (at "90 System/Capture Log.md") via mcp__basic-memory__read_note. Scan each line that starts with "{" as JSON.

Find the most recent entry where source == "granola" **and mode == "create"**. Record its ts value as LAST_CAPTURE.

The mode filter is load-bearing. A "skipped" entry records that a run *fired and failed*; a "noop" records that it fired and found nothing. Neither means data was captured. Selecting the most recent entry of any mode lets every failed run stamp a fresh cursor and advance it past the very window it failed to process — which is how this job silently captured nothing for four months while reporting "nothing new".

Then clamp the window:
- If no "create" entry exists, use a timestamp 25 hours ago.
- If LAST_CAPTURE is more than **7 days** before now, do NOT backfill the whole gap. Use now minus 7 days as the effective start, and say so in your final output line: state the true LAST_CAPTURE, the size of the unprocessed gap, and that a longer backfill needs the user to ask for it. A job that has been dead for months must never perform a months-long unattended write.

Step 2 — List recent meetings.
Call mcp__claude_ai_Granola__list_meetings with no filter. From the result, select meetings where start_time is after (LAST_CAPTURE minus 1 hour) to catch any late-processing transcripts. If the result is paginated, fetch all pages.

Step 3 — Deduplicate.
For each candidate meeting, check the "Capture Log" note (already read in Step 1) for an existing entry with source == "granola" and detail.meeting_id == this meeting's id. Skip any that already have a ledger entry.

Step 4 — Fetch and write each new meeting.
For each meeting that passes dedup:

  a. Call mcp__claude_ai_Granola__get_meeting_transcript with the meeting id.
     If the transcript body is empty or null, skip this meeting (not yet processed).

  b. Privacy check: scan the meeting title and transcript body for any of these keywords (case-insensitive):
     Match on WORD BOUNDARIES, not substrings, and prefer the specific phrase over the bare word:
       salary, compensation, bonus, severance, equity grant, offer letter, performance review, PIP,
       health insurance, mental health, medical, doctor, diagnosis, therapy, family, bereavement,
       1:1, one-on-one, HR, benefits enrollment, pay raise, merit increase, personal leave

     Two failure modes this list is written to avoid:
     - Substring bleed. Bare "comp" matches Company/Comparison/Complete; "PIP" matches Pipeline;
       "personal" matches Personalization. Always require word boundaries.
     - Semantic over-breadth. Bare "health" matches "Delivery Project & Team Health" and
       "Project health check" — ordinary delivery meetings — even WITH word boundaries, which is
       why it is replaced by "health insurance" / "mental health" / "medical". Same for bare
       "raise" ("Raise the bar workshop") -> "pay raise" / "merit increase".

     When a match comes only from the title and the transcript body does not corroborate it,
     prefer PERSONAL = false. Mis-routing a sales-pipeline meeting into the personal hub is a
     real, observed failure — not a hypothetical.
     Set PERSONAL = true if any keyword matches, false otherwise.

  c. Build the vault path:
     - date: meeting start_time formatted as YYYY-MM-DD
     - slug: title lowercased, spaces to hyphens, non-alphanumeric stripped, truncated to 60 chars
     - path: 04 Knowledge/Meetings/<date>-<slug>.md
     If PERSONAL == true, route to personal hub vault instead (same relative path).

  d. Build the vault file content in this format:
     ---
     source: granola
     meeting_id: <id>
     title: <title>
     date: <YYYY-MM-DD>
     attendees: <comma-separated attendee names if available>
     granola_url: <url if available in the meeting object>
     captured_at: <ISO timestamp of now>
     personal: <true|false>
     ---

     # <title>

     **Date:** <YYYY-MM-DD>
     **Attendees:** <names or "not listed">
     **Granola link:** <url or "not available">

     ## Transcript

     <full transcript body, verbatim>

  e. Write via mcp__basic-memory__write_note to the computed path. If the path already exists, append -2 to the slug and retry once.

  f. Append one ledger event to the vault note "Capture Log" (at "90 System/Capture Log.md") via:

       mcp__basic-memory__edit_note(
         identifier="Capture Log",
         operation="append",
         content="<json-line>\n"
       )

     The content must be ONE JSON object per call, on a single line, terminated with \n. Schema:
       {"ts":"<ISO8601 UTC>","source":"granola","detail":{"meeting_id":"<id>","title":"<title>"},"output":"<vault path written>","mode":"create","bytes":<byte length of written content>}
     Add "redacted": true to detail when PERSONAL == true.

Step 5 — If zero new meetings were found and written, exit silently (no output).
If one or more were written, output a single line: "Captured N Granola meeting(s): <titles joined by comma>."
Do not output anything else.
