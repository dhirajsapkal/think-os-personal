# Learnings

Cross-project, reusable decisions / patterns / lessons. Tagged for discovery. Append-only. Append via `/capture` or by hand.

The point of this file: when I start something new, surface what I already know.

---

## Format

```markdown
### YYYY-MM-DD — <short title>
- **Context**: where this came up (project, conversation, meeting)
- **Learning**: the reusable insight, decision, or pattern
- **Applies to**: future engagement types where this is relevant
- **Tags**: #tag1 #tag2 #tag3
- **Source**: link to project file, Figma, doc, Slack thread, etc.
```

## Entries (newest first)

### {{YYYY-MM-DD}} — Example: kicking off a design system needs a buyer, not just a sponsor
- **Context**: Client engagement, month two; sponsor wanted it, no team mandated to adopt.
- **Learning**: A design system needs an *adopter* commitment from at least one product team before it gets built, otherwise the artifacts sit unused. Sponsor approval alone is not enough.
- **Applies to**: Any design system kickoff. Any internal platform initiative.
- **Tags**: #design-system #kickoff #stakeholders
- **Source**: project notes / retro doc.

### {{YYYY-MM-DD}} — Example: write the failure mode before the success metric
- **Context**: AI feature kickoff; team kept stalling on success metrics.
- **Learning**: It's faster to define what "this didn't work" looks like first, then derive metrics that would catch that failure. Working backwards from failure modes surfaces the right metric within an hour; success-first conversations sprawl for a week.
- **Applies to**: Any AI feature spec. Any new product hypothesis.
- **Tags**: #ai #strategy #discovery
- **Source**: workshop facilitation notes.
