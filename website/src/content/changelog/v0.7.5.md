### Highlights

- **New always-on instruction block** (`70-claude-ai-bridge.md`, ~55 lines) teaching the agent what the claude.ai marketplace bridge is and how deferred tools load
- **`/thinkos-mcp-help` rewritten** — "vault index vs. runtime tools" are now explicitly two separate surfaces, with a table
- A checklist the agent must run before ever telling you "X is unavailable"

### What happened

The trigger: a Claude Code session said *"Claude Code CLI does not have Slack tools exposed... Think OS itself does not provide Slack access"* — and cited `/thinkos-mcp-help`'s line that the index doesn't pull from connectors. True statement about the index; wrong conclusion about the agent. `claude mcp list` showed the Slack connector active and the send-message tool loadable via `ToolSearch`. The reasoning was anchored in the Think OS docs, which made it the docs' bug.

### What changed

Every session now starts with explicit guidance: `mcp__claude_ai_*` tools exist as deferred tools, they need `ToolSearch` to load before being callable, and the vault index's coverage gaps are not evidence the agent can't reach those services. The closing line of the rewritten skill section says it plainly: *"'The vault doesn't have your Slack messages yet' and 'the agent can't reach Slack' are different statements."*

Small content release — no new scripts, no behavioral changes to existing commands.

**Upgrade:** existing installs pick up the new block on the next `/thinkos-update`.
