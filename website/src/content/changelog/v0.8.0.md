### Highlights

- **5-stream code review found 113 findings** across bugs, security, agent traps, redundancy, drift, and deploy-readiness — 23 P0, 42 P1, 36 P2, 12 P3
- **21 parallel Sonnet agents fixed 96 of them** in a single release, executing 43 structured work packages from a synthesis plan
- **Four security ship-blockers closed**: shell injection in `catalog.sh`, non-atomic CLAUDE.md write, `eval` in uninstaller, unpinned `uvx granola-mcp`
- **13 P2/P3 findings deferred to v0.9**; four human-input gates (legal/DPA, IT review, enterprise mode, GPG signing) documented as company-rollout prerequisites

### Why this release exists

v0.7.4 through v0.7.6 each fixed one instance of a pattern. v0.7.4 caught a silent install-skip from a loose `grep`. v0.7.5 caught an agent-trap docstring that misled a separate Claude session about Slack availability. v0.7.6 caught three features that had been claimed-as-shipped since v0.5.0 without ever being wired up.

Three releases in one day was the signal that the pattern was systemic. v0.8 is the release that goes wide instead of deep — five parallel reviewer agents scanned every script, instruction file, slash command, catalog entry, template, and doc page. The same patterns that v0.7.4–v0.7.6 each caught one of were sitting in three more places each. The full review plan with per-finding fix instructions lives at `.plans/2026-05-18-comprehensive-review/plan.md` in the repo.

### Security

Four findings would have blocked a responsible company-wide deploy. All closed:

- **Shell injection in `scripts/lib/catalog.sh`** — three functions interpolated shell variables into Python heredoc source. Refactored to argv-passing; the eval-based `catalog_yq` helper is removed entirely.
- **Non-atomic CLAUDE.md write** — `install_marked_block()` redirected directly to the target file, truncating before rendering the replacement. SIGTERM or disk-full would empty `~/.claude/CLAUDE.md`. Now uses the `mktemp → mv` atomic pattern.
- **`eval "$extracted"` in the uninstaller** — replaced with base64-encoded explicit per-key parsing so the bash side never sees an unquoted shell string from `install-manifest.json`.
- **`uvx granola-mcp` unpinned** — up to 14 PyPI fetch-and-executes per day with full user permissions. Pinned to `granola-mcp>=0.1`. Exact-version pinning deferred to v0.9 pending vendor audit.

Also closed: root-invocation guards on five entry-point scripts, LaunchAgent logs at 644 → 700, `install-manifest.json` at 644 → 600, shared-mode coverage gaps for `build_context` and `recent_activity`, sensitive-path pre-check in vault sync, three more unanchored-grep silent-skips beyond the one v0.7.4 caught.

### Agent traps closed

The "connectors live in desktop agent" misframing that v0.7.5 fixed in `/thinkos-mcp-help` lived in four more slash commands. `/thinkos-plate`, `/thinkos-morning`, `/thinkos-reindex`, and `/thinkos-stale` now all carry the bridge clause: if `claude mcp list` shows the connector connected via `claude.ai *`, the agent can reach the service directly via `mcp__claude_ai_<Service>__*` tools without telling the user to go to the desktop agent.

Other behavioral correctness fixes: `/thinkos-capture` decision mode now uses `prepend` (was `append`, contradicting the documented "newer at top" convention); `/thinkos-voice` description matches behavior; `/thinkos-reindex` resolves the active vault's `bm_project` from `vaults.json` instead of hardcoding `think-os`; the Linear vs Jira disambiguation in `/thinkos-capture-setup` no longer silently writes Jira data to files named `linear-*`.

### Drift fixed

- **Session-capture was writing to the pre-v0.4.2 `~/.thinkos/capture-log.jsonl` path** while every other component used the vault note `90 System/Capture Log.md`. Every autosave user had been silently losing capture events from the audit trail. Now writes only to the vault note.
- **Seven slash command files referenced as installed didn't exist**: `thinkos-doctor`, `weekly-review`, `quarterly-review`, `recent-log`, `draft-reply`, `validate-os`, `index-projects`. All created with appropriate playbook bodies.
- **Linear capture-setup installed a launchd task whose dispatcher case didn't exist**. Now wired end-to-end OR cleanly disambiguated from Jira when the bridge supports one but not the other.
- **`setup/manifest.yaml` and `AGENTS.md` had stale `composed_with` / curated instructions lists** missing `70-claude-ai-bridge.md`. Both now list all 9 blocks.
- **10 catalog URLs with `TODO: verify` comments** are now declared `available: false` with a `url_verified: false` field that survives JSON serialization. `linear` and `ms365` are out of presets pending verification.

### Token efficiency

Adapter `instructions.md` went from 122 lines to 83 lines by removing five sections that duplicated content already in the priority preamble or `30-think-os-write-targets.md`. The four shared bash functions that were copy-pasted between `setup.sh` and `update.sh` — and which caused the v0.7.4 drift bug — are now extracted into `scripts/lib/render-instructions.sh` and sourced by both.

### Added

- **`url_verified` and `trust_level` fields on catalog entries** so downstream tools can distinguish verified vendor endpoints from `third-party-unverified` (granola) from `anthropic-official` skill bundles.
- **`scripts/lib/lint-catalog.sh` CI lint** that fails on `TODO` URLs, unverified-in-presets, YAML/JSON drift, or preset references to nonexistent catalog ids.
- **`templates/.gitignore` and `templates/90 System/Capture Log.md`** — the latter was referenced by 8 cron prompts and 4 scripts but had no shipped template, so fresh installs would fail on first capture.
- **Data disclosure phase in `setup/manifest.yaml`** — one-paragraph explanation of which cron tasks send vault content to Anthropic via `claude -p` and which run fully local. Full opt-out path is a v0.9 item.
- **`THINKOS_MASK_CWD=1` env var** for consultancies whose directory names encode client names — masks `cwd` to its basename in the session-capture ledger.
- **Log rotation cap, plist path doctor check, session-capture project filter** — defense-in-depth additions described in the review.

### Deferred to v0.9

13 P2/P3 findings tracked but not addressed in v0.8. Four human-input gates documented as company-rollout prerequisites: Anthropic DPA review (does sending vault-derived prompts via `claude -p` need a Data Processing Agreement?), MDM-compatible enterprise mode, Basic Memory IT review process, full GPG-signed commit verification for `--pull`. The full deferred list and the four gates live in `.plans/2026-05-18-comprehensive-review/plan.md` §9–§10.

### Why this matters

Each prior release fixed one instance of a pattern while three more sat in the codebase waiting to surface. v0.8 closes those gaps in one structured pass and adds the lint that catches the next instance. The security findings move Think OS from "fine for a personal install" to "deployable to ~100 colleagues at a consultancy" with the four caveats explicitly documented rather than buried as risks.

### Upgrade

```bash
/thinkos-update --pull
```

You'll see a new `Note: GPG signature verification is deferred to v0.9` line — that's intentional, and points at the diff command for reviewing what landed in your install.
