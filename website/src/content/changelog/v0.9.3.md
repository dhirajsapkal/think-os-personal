### Highlights

- **Instruction-stack diet: ~9.3k → ~4.5k tokens per session** — three blocks became on-demand skills (bridge guide, shared-mode spec, seeding save-flow); passive triggers like redaction and drift nudges stayed resident, because a skill the model never loads is a behavior that never fires
- **Measured per-command savings** — `/thinkos-morning` ~17.6k → ~8.2k tokens, `/recent-log` ~20.2k → ~6.2k, `/thinkos-capture` ~9.6k → ~2.0k, a trivial question ~10.9k → ~4.7k
- **Retrieval doctrine** — searches default to `page_size=3` (~520 tokens vs ~1,620, same top-3 recall) with an explicit escalation ladder; snippets are pointers, never answers
- **Freshness is now mechanical** — a `SessionStart` hook opens stale sessions with one line (`CURRENT FOCUS STALE: … run /weekly-review`), `/weekly-review` replaces-and-prunes Current Focus, and non-CLI surfaces get a tiny Focus Freshness note
- **Index hygiene** — doctor detects Basic Memory FTS index drift against actual entity counts and recommends `/thinkos-reindex`; it caught real live corruption caused by concurrent per-session servers
- **`docs/why-files-not-a-database.md`** — the canonical, steelmanned answer to "shouldn't this be a vector/graph DB?" Verdict: the migration reduces to a compact deterministic view plus an index fix — keep the files
- **Website refresh** — self-hosted editorial type (Newsreader / Hanken Grotesk / IBM Plex Mono), reduced-motion-safe animation, research-backed positioning, and this redesigned changelog

### What changed

The release started as a challenge: *markdown files? shouldn't this be a real memory database?* A 22-agent research study — live measurements of the deployed system, adversarial verification, two independent judges on every load-bearing figure — answered it. The waste was never the files. It was a 9.3k-token preamble re-sent every session, full-file reads of the Work Log / Capture Log / Tasks where one section was needed, a search default three times more expensive than its recall required, and a freshness rule written in prose that nobody executes (Current Focus ran 17 days stale).

So every fix is a parameter, a heading anchor, a shell extraction, or a hook. `/recent-log` now date-windows the Work Log with a read-only script instead of reading all of it; capture dedup tails the last 30 ledger lines; morning and plate extract exactly the `## Today` section of Tasks. Vault writes still go through Basic Memory exclusively — only deterministic read-only extraction moved to the shell. New `supersedes:` and `aliases:` conventions on Decisions and People give the markdown the two things memory databases genuinely do better — temporal edge validity and entity resolution — deterministically, with zero per-write LLM cost.

And the one genuine database exhibit argued *for* the design: the live FTS index had silently accumulated duplicate rows from concurrent sessions racing the indexer. A derived-cache bug — the markdown was never wrong, and one reindex repairs everything from the files. Doctor now detects exactly that drift, an upstream issue is drafted, and the single-shared-server posture is documented.

One more gap the live system exposed: session capture filters to your vaults plus `tracked_projects` — and nothing ever populated that list, so on real installs the filter matched zero sessions for weeks without anyone noticing. Onboarding now asks where your project work lives (the answer flows through `--tracked-projects`), and existing installs add folders any time with `scripts/thinkos-vault.sh track <path>`.

### Upgrade

`/thinkos-update --pull` picks up v0.9.3 normally — it installs the three new skills to `~/.claude/skills/`, merges the SessionStart hook into `~/.claude/settings.json` (idempotently, preserving your existing hooks, with a backup), and rewrites the slimmed instruction block.
