### Highlights

- **New `/thinkos-refresh` command** — sweeps Gmail, Slack, Calendar, ClickUp, Atlassian, Notion, and Granola, then rewrites `01 Now/Tasks.md` with a fresh `last_synced` timestamp
- `--quick` mode (four sources, ~15s), `--source <name>` for a single connector, `--dry-run` to preview the diff
- Six skills and two templates that still referenced the retired `productivity:update` skill now point at the new command

### What changed

A real gap surfaced mid-session: `Tasks.md` told the agent to refresh via `productivity:update`, a skill that no longer exists in the `/thinkos-*` namespace — and six other skill files referenced it as a fallback. `/thinkos-refresh` closes the gap. It pulls connectors in parallel, applies the per-source filter rules from `Connectors.md`, preserves your manually-added section and the weekly done-list verbatim, appends a capture-log event on every run, and degrades gracefully — one unavailable connector doesn't fail the whole sweep. Portable across surfaces via the claude.ai bridge with native MCP fallback.

### Why this is a patch, not a minor

The versioning rule got tightened alongside this release: patch releases cover hotfixes *and* small additive features that fit the current milestone framing; minor bumps are reserved for coherent, nameable milestones. `/thinkos-refresh` is genuinely additive but fits under v0.9's "stable with external contributors" framing. Reading the old rule literally would have made every new skill a minor bump — v0.20.0 by month-end with nothing like v1.0 maturity.

### Upgrade

`/thinkos-update --pull` picks up v0.9.1 normally.
