### Highlights

- **`/thinkos-update` self-heals launchd jobs after a repo move** — stale `com.thinkos.*.plist` script paths are detected and the matching installer re-run, preserving each job's label, schedule, and `--vault` args
- **Uninstaller finally reads v2 manifests** — every fresh install since v0.9.0 writes v2, which the uninstaller rejected, silently skipping the managed-file teardown
- **Doctor stops reporting clean on broken probes** — drift, ledger, and 24h-volume checks now warn "state unknown" instead of defaulting to a healthy-looking `0`; new `catalog:lint` check runs on every invocation
- **Script hardening** — catalog argv injection closed, plist paths XML-escaped, vault-sync sensitive-path guard widened to tracked modifications, EXIT-trap preservation, glob guards
- **Truth pass everywhere** — last `productivity:update` references removed, maintainer-specific content scrubbed from shipped templates and playbooks, docs corrected (no Stop hook ships; Layer A/B/C naming unified; emergent-seeding state lives in the vault), and the website's claims rebuilt from reality

### What changed

A five-stream fix sweep — scripts, templates, adapters, docs, website — with every stream independently re-verified against the working tree before landing. The launchd refresh was exercised against a live install with ten stale plists; the uninstaller's manifest loader against synthetic v1/v2/v3 manifests; the XML escaping against a hostile vault path; the doctor's new fallbacks through a JSON round-trip.

The shared theme of the script fixes: infrastructure that fails *silently* is worse than infrastructure that fails loudly. Stale launchd jobs kept "running" against a moved repo for as long as nobody read the logs. The uninstaller saw a v2 manifest and reported "no manifest." A doctor probe that crashed reported a clean install. All three now either work or say loudly that they didn't.

The same standard applied to published words. `docs/continuous-capture` claimed session capture runs via a Claude Code Stop hook — it's a 2-hourly launchd job, and the doc now says so. The emergent-seeding doc pointed at a state file that contradicted the shipped instructions. The homepage claimed twenty-seven slash commands when thirty-six ship, and ~280 lines of curated instructions when it's ~500. The site's version stamp is now read from the repo's `VERSION` file at build time (`src/lib/version.ts`), the changelog preview renders from the real content collection, seven missing changelog entries are backfilled (v0.7.1–v0.7.6, v0.9.1), and the site finally has a 404 page.

Also in this release: a new `90 System/Emergent State.md` template (referenced by the emergent-seeding spec since v0.7.6 but never shipped), three spec gaps in emergent seeding closed, a Rename branch for `/thinkos-vault`, the `/thinkos-reindex` bm_project lookup fixed, the `/thinkos-doctor` flags table reconciled with the script's real arguments, and the Business Brain template fully genericized so it no longer ships one company's strategy to everyone's machine.

### Upgrade

`/thinkos-update --pull` picks up v0.9.2 normally — and on this release specifically, the update itself will repair any launchd jobs left stale by a past repo move.
