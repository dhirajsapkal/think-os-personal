### Highlights

- **`copy_templates()` now excludes `templates/LaunchAgents/`** — three plist templates with `__SCRIPT_PATH__` / `__LOG_DIR__` placeholders were being copied into every v0.8.0 vault by accident
- **`/thinkos-autosave` and `/thinkos-capture-setup` skills now resolve `$REPO_ROOT` explicitly** — no more "resolved from..." hand-waving that let agents miss the install scripts
- **`thinkos-doctor.sh` detects leaked plists** in existing v0.8.0 installs and prints the exact cleanup command

### The actual diagnosis

A user installed v0.8.0 and his Claude session told him: "session capture is partially bundled but not fully functional — the LaunchAgent plist template exists in your vault with unresolved placeholders, there's no install script to process it, the capture shell script doesn't exist."

Two of those three claims were wrong: `scripts/install-session-capture.sh` and `scripts/thinkos-session-capture.sh` both exist and work. The user's `/thinkos-autosave on` invocation would have called them via the skill.

But the third claim was right: three plist templates *were* sitting in the vault with literal `__SCRIPT_PATH__` text. The agent saw them, never traced the install path to the repo (`/thinkos-autosave` skill body), and concluded the install was incomplete.

### What changed

`scripts/thinkos-setup.sh:copy_templates()` had explicit `continue` clauses for two non-vault template directories — `instructions/` (the curated agent-instruction stack) and `team/` (the project-vault template skeleton). It was missing the same exclusion for `LaunchAgents/` (the launchd plist templates). One-line fix per loop; both loops in the function now skip the directory.

The two relevant skills got the same defensive rewrite. Every shell invocation that runs an install script now starts with:

```bash
REPO_ROOT="$(python3 -c "import json,os; print(json.load(open(os.path.expanduser('~/.thinkos/install-manifest.json')))['repo_path'])" 2>/dev/null)"
```

…and then uses `bash "$REPO_ROOT/scripts/install-launchd-job.sh"` rather than the brittle `bash scripts/install-launchd-job.sh` (which only resolved if the CWD happened to be the repo). The skill also adds an explicit "never look inside the vault for install scripts" sentence so future agents can't repeat the diagnostic error even if some other infrastructure file leaks somewhere.

### Migration for existing installs

If you installed v0.8.0 or earlier:

```bash
bash <repo>/scripts/thinkos-doctor.sh
```

…will warn you about leaked plists with the exact `rm -rf` command to clean them up. Or you can just delete them directly:

```bash
rm -rf "$HOME/ThinkOS/vault/LaunchAgents"
```

The doctor check stays silent on new installs (where the directory never gets created). Run `/thinkos-update --pull` to pick up the v0.8.1 setup + skill fixes.
