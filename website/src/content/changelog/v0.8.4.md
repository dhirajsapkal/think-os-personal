### Highlights

- `/thinkos-capture` decision-mode now uses `identifier="Decisions"` (was `"Standing Decisions"`)
- `/thinkos-decisions` read fallback fixed the same way
- Both fixes one-character changes in their respective skill files

### What happened

Mid-session `/thinkos-capture` run today, session-recap mode. The decision draft was approved, the skill called `edit_note(identifier="Standing Decisions", operation="prepend", ...)`, and Basic Memory dutifully **created a new note** at `Standing Decisions.md` instead of prepending to the existing `04 Knowledge/Decisions.md`.

The cause: Basic Memory's `edit_note` identifier matches on the note's `title` field (set in frontmatter), not on the H1 heading inside the body. The canonical decisions file has frontmatter `title: Decisions` and a body that opens with `# Standing Decisions` — easy to confuse if you're authoring a skill template by glancing at the file's body.

Caught the orphan inside the session, deleted it, and re-prepended to the correct identifier. The skill template was still wrong though — would have repeated the same bug on every future session-recap that captured a decision. Hence this hotfix.

### What changed

Two one-character edits in two skill files:

- `adapters/claude-code/commands/thinkos-capture.md` line 51 — `"Standing Decisions"` → `"Decisions"`
- `adapters/claude-code/commands/thinkos-decisions.md` line 9 — `"Standing Decisions"` → `"Decisions"`

The `/thinkos-decisions` read fallback was the less destructive of the two — a `read_note` on a missing identifier just returns "not found." The capture write was the real bug since it silently created an orphan. Both are fixed in the same pass.

### Broader lesson

Any Basic Memory identifier in a curated skill should be cross-checked against the actual note's `title` field rather than copied from whatever heading is at the top of the body. Worth a small audit pass on the other commands that reference vault notes by name — not part of this hotfix, but on the radar.

### Upgrade

`/thinkos-update --pull` picks up v0.8.4 normally.
